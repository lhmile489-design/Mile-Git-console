## 4. 逐项方案

### A2 收尾：进度与取消

渲染层：

- store 增加 `remoteProgress: { op, stage, progress } | null`。订阅 `git:progress`（用 `on()` 返回的取消订阅函数清理），只接收当前活动仓库的事件。
- 新增 `cancelRemote()`：调用 `git:remote:cancel`。远端操作结束（成功、失败、取消）都清空进度。
- 返回码 1006 视为用户主动取消：给一条普通提示「已取消」，不弹红色错误。`_invoke.ts` 目前遇到非 0 一律抛 `Error`，需要让它保留错误码（例如抛带 `code` 字段的错误），这样 store 才能区分 1006。
- ActionBar：操作进行时，按钮上显示阶段文字和百分比（receiving 显示为「接收对象 45%」之类的中文）；2 秒后在按钮组旁出现「取消」。

需要实测确认的点：

- simple-git 的进度事件只有在 git 带 `--progress` 时才会有输出，需要用真实的 fetch 验证事件确实到达渲染层。
- abort 会终止 git 子进程。取消 pull 时可能留下半完成的合并或 `.git/index.lock`，要实测取消后仓库状态是否干净。
- 同一仓库重复触发远端操作时，后端会返回「该仓库已有远端操作正在进行」，要确认界面上按钮在此期间确实是禁用的。

验收：取消一次真实 fetch 后，列表恢复可用、没有残留锁文件、提示为「已取消」；进度文字能随阶段变化。

### A9 提示卡片

- store 的 `error` 与 `notice` 两个字符串改为 `toasts: Toast[]`，`Toast = { id, kind: 'error' | 'success' | 'info', text, action?: { label, onPress }, sticky }`。
- 兼容策略：保留现有 `set({ notice })`、`set({ error })` 的调用点语义，在 store 内加 `pushToast`，逐个替换调用点。实施时先用 grep 统计调用点数量，再决定一次改完还是分两步。
- 展示：最多同时 3 条，新的在下；错误不自动消失，普通提示 3 秒，带操作按钮的 5 秒；鼠标悬停时暂停计时。
- 无障碍：错误用 `role="alert"`，普通提示用 `role="status"`，容器本身加 `aria-live`。

验收：连续触发 4 条提示，只显示最新 3 条，旧的按顺序消失；带「查看详情」按钮的提示能点击并关闭。

### A3 快捷键

- 新建 `commands/registry.ts`：一份命令列表，每条有 `id`、`label`、`shortcut`、`enabled()`、`run()`。快捷键和（后面的）命令面板都从这里取。
- 键位：F5 刷新状态；Ctrl+1 切到「更改」；Ctrl+2 切到「历史」；Ctrl+Shift+P 推送；Ctrl+Shift+L 拉取。macOS 用 Cmd 代替 Ctrl。
- 在渲染层统一监听 `keydown`。有对话框打开、焦点在输入框里时，只响应不会和输入冲突的键。
- 菜单项和按钮的 `title` 上显示快捷键。
- 需要验证 F5：Electron 在没有菜单时 F5 是否会触发整页重载，如果会，必须 `preventDefault`。另外 `optimizer.watchWindowShortcuts` 在生产模式会拦截 Ctrl+R，要确认和我们的键位不冲突。

验收：在更改视图按 Ctrl+2 切到历史，F5 触发一次静默刷新且页面不重载；输入框聚焦时按 F5 仍然刷新，按 Ctrl+Shift+P 不会在输入框里插入字符。

### A6 提交草稿

- 草稿按仓库 id 保存摘要和描述。切换仓库时各自保留，提交成功才清空，提交失败保留。
- 存储位置：渲染层 `localStorage`，键 `draft:<repoId>`。不走 `settings:set`，避免给那个通用写入口增加新的使用方（它在上一轮审查里被指出没有 key 白名单）。
- 草稿内容不是凭据，不涉及安全红线。移除仓库时同时删除对应草稿。
- 写入做 300ms 防抖。

验收：在仓库 A 输入摘要，切到仓库 B 再切回，内容还在；重启应用后仍在；提交成功后清空；移除仓库后对应键消失。

### A5 窗口状态

- 主进程用 `electron-store` 记 `window.bounds` 和 `window.maximized`，在 `resize`、`move` 时防抖保存，`close` 与退出时保存最终值。
- 启动时先校验保存的位置落在某个显示器的可见范围内（用 `screen.getAllDisplays()`），否则回退到默认大小并居中，避免外接显示器拔掉后窗口出现在屏幕外。
- 保持 `minWidth 1024`、`minHeight 700`。
- 最大化状态单独记，最大化时不覆盖「还原」时的尺寸。

验收：改大小和位置后重启，窗口恢复；把保存的坐标手动改成屏幕外，启动后窗口仍然可见；最大化后重启仍是最大化，点还原回到上一次的普通尺寸。

### A7 仓库失效处理

- `repo:list` 的返回项增加 `missing: boolean`（主进程用 `fs.existsSync` 判断，不改数据库表，所以没有迁移脚本）。`useFocusRefresh` 触发时顺带重新取一次列表。
- 新增 IPC `repo:relocate`：弹出文件夹选择，校验是 Git 仓库且路径没被其他记录占用，更新该记录的路径。
- 列表项失效时显示「路径不存在」标记。选中失效仓库时，右侧显示专门的空状态，提供「重新定位」和「移除」两个按钮，不再去调用 git。

验收：把测试仓库的文件夹改名后回到应用，列表项显示失效；点「重新定位」选回改名后的文件夹，恢复正常；选一个非 Git 文件夹会得到明确的错误提示。

### A8 拖拽导入与托盘提示

- 拖拽：在窗口上监听 `dragover` 与 `drop`，只接受文件夹，拖入时显示一层「松开以导入」的覆盖提示。
- 先验证的风险：当前是 Electron 33，渲染进程里 `File.path` 已被移除，需要在 preload 里用 `webUtils.getPathForFile` 取路径。实施第一步就是写一个最小原型确认这条路能通；如果 File 对象无法穿过 `contextBridge`，改成在 preload 内部监听 `drop` 并只把路径字符串交给渲染层。
- 托盘提示：主进程在第一次拦截关闭并隐藏时，通过一个新的监听 channel 通知渲染层，渲染层用 A9 的提示卡片显示「已最小化到托盘，右键托盘图标可退出」。是否已提示过记在 `tray.hintShown`。设置页的开关留到阶段 D 的设置页补全，这一项里只做「只提示一次」。
- 与阶段 E 的关系：E1 会重写 `close` 拦截逻辑（区分用户点关闭和应用退出）。A8 只在现有拦截的分支上加一次通知，不动拦截本身，避免和 E1 冲突。

验收：把文件夹拖进窗口后仓库被导入并选中；拖入非文件夹给出提示；第一次点关闭出现托盘提示，第二次不再出现。

### A4 命令面板

- Ctrl+K 打开，居中的 `Modal` 加输入框和结果列表。`react-aria-components` 1.22.0 自带 `Autocomplete`（在 node_modules 里确认存在），优先用它做过滤和键盘导航，不够用再自己写。
- 命令来源：A3 的命令注册表（刷新、切换视图、获取/拉取/推送、打开设置）加两类动态项：切换仓库（取自仓库列表）、切换分支（取自本地分支）。
- 最近使用的命令排在前面，记在 `localStorage`。
- 不可用的命令（例如没有远端时的推送）灰显并说明原因，不直接隐藏。
- 快捷键提示直接显示在每条命令右侧。

验收：Ctrl+K 打开，输入「历」能找到「切换到历史」，回车执行并关闭；上下键、Esc 可用；切换分支项能真正切换；打开时背景不可操作，关闭后焦点回到原位置。
